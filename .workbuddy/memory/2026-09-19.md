## SettingMenu 组件从 Canvas 搬到 Panel（已改）

理由：Panel 是「最小能包含全部按钮的节点」，脚本管的是按钮堆而不是整个 Canvas。
挂 Canvas 上会让 `GetComponentsInChildren<Button>()` 扫到无关 UI，且禁用语义不干净。
（历史原因：Panel 是后加的容器，脚本没跟着挪。Opening 场景压根没有 OpeningButton，
Setting 是独立演化的。）

改动：
- `Assets/Scripts/UI/SettingMenu.cs`：兜底路径 `Find("Panel/BattleSpeed")` → `Find("BattleSpeed")`
  （组件现在挂在 Panel 上，BattleSpeed 是直接子物体）；类注释更新为「挂在 Panel 上」。
- `Assets/Scenes/Setting.unity`：SettingMenu 组件(fileID `1542338969`)从
  Canvas(`1542338964`) 的 m_Component 移到 Panel(`1107696162`)，
  `m_GameObject` 同步改为 Panel。Canvas 只剩 RT/Canvas/CanvasScaler/GraphicRaycaster。

### 搬迁操作要点（Unity YAML 组件搬移）
组件搬家 = 三步，缺一不可：
1. 改组件块的 `m_GameObject:` 为目标 GO
2. 源 GO 的 `m_Component` 列表删掉 `- component: {fileID: X}`
3. 目标 GO 的 `m_Component` 列表**末尾**追加（Transform/RectTransform 必须仍在第一位）
搬运是**净零**改动，字节数不变。校验要额外做两项：
- 每个组件只能出现在**一个** GO 的 m_Component 里（查重复归属）
- 每个组件的 `m_GameObject` 必须与「包含它的那个 GO」一致（交叉校验）

### 发现：Unity 重新序列化会改我写的数组
上次补丁写入的 `speedButtons` 有 4 项，用户在编辑器打开保存后变成 **5 项**，
末尾多了 `- {fileID: 0}`。这是 Unity 对 null 元素的补齐行为，不是错误
（代码里 `speedButtons[i] == null` 已跳过）。但说明：**改完场景 YAML 后，
只要用户在编辑器里打开过并保存，我的假设就可能失效，必须重新读文件再动手。**
