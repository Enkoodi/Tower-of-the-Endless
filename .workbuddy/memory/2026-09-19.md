### 搬迁操作要点（Unity YAML 组件搬移）
组件搬家 = 三步，缺一不可：
1. 改组件块的 `m_GameObject:` 为目标 GO
2. 源 GO 的 `m_Component` 列表删掉 `- component: {fileID: X}`
3. 目标 GO 的 `m_Component` 列表**末尾**追加（Transform/RectTransform 必须仍在第一位）
搬运是**净零**改动，字节数不变。校验要额外做两项：
- 每个组件只能出现在**一个** GO 的 m_Component 里（查重复归属）
- 每个组件的 `m_GameObject` 必须与「包含它的那个 GO」一致（交叉校验）

## ⑦ 那两个字段的真相（git 考古，23:25）

用户猜测它们是用来「判断击败的一击不算敌人反伤」的。**规则确实存在，但载体不是这两个字段。**
规则实现在 `BattleManager` 的两个 HP 守卫里（不是 `lastDamage*`）：

- 玩家攻击侧（`BattleManager.cs:284-292`）：`steal` 先无条件结算 → `if (enemy.HP > 0)` 才算敌人的反伤。
- 敌人反击侧（`BattleManager.cs:317-325`）：`enemySteal` 先无条件结算 → `if (playerData.HP > 0)` 才算玩家的反伤。
- 注释原文：「反伤仅在敌人未因本次攻击死亡时触发（吸血已先结算）」

**git 证据**：
- `git show 2a21fa3 -- Assets/Scripts/Core/BattleManager.cs` → 这个提交（v0.1，2026-08-21）
  正是把**无条件反伤**改成**加 HP 守卫**的那一次，注释也是那时写的。所以规则一开始就是 HP 判定。
- `git log -S "lastDamage"`（全仓库）**只返回一个提交**：`57c347b`
  （2026-06-30「feat:完成了部分特殊祝福」）—— 而它是**引入**这两个字段的提交。
  之后没有任何提交改变过它们的出现次数 ⟹ **从未有过任何一次读取**，
  不存在「曾经用过后来被换掉」。它们从诞生起就是只写不读。

**顺带解开了 ⑤ 图鉴口径差异的来历**：同一次 v0.1 还改了吸血基数
```
- int steal      = actualToEnemy  * playerData.LifeSteal / 100;   // 按实际打出的伤害
+ int steal      = playerPhysical * playerData.LifeSteal / 100;   // 按理论物理伤害
- int enemySteal = actualToPlayer * enemy.LifeSteal / 100;
+ int enemySteal = enemyPhysical  * enemy.LifeSteal / 100;
```
而 v0.1 对 `MonsterManualEntryUI.cs` 只改了 **2 行显示文案**（把「反伤」加进属性行），
**没同步模拟公式**。图鉴里 `actualToPlayer * enemy.lifeSteal`（`MonsterManualEntryUI.cs:132`）
就是 v0.1 之前的旧口径 —— 所以不是图鉴写错，是实战改了它没跟上。

**相邻小瑕疵**：玩家被反伤打死时不会立刻收场 —— 反伤（`SubtractHP`，无下限保护）之后
还会走完 `ComputeRoundDamage` → 敌人反击（对 0 血玩家再打一次，日志照写
「敌人反击，造成 X 点伤害」）→ 才在 L332 判 `IsDead`。最终判负结果一样，只是多一条日志 +
多播一次受伤动画。未修。

## 数值口径第三轮修正（23:42）—— 扣血下限 + 吸血不乘生命系数

敌人侧本来就没问题（`EnemyController.Heal` 是 `hp += amount`，无系数）。

**`Heal()` 的保留语义**：给「成长性回复」用（会乘 hpMultiplier，和 `AddHP` 同口径）。

## 项目里目前有三套伤害公式（排查时别搞混）

| 位置 | 状态 | 用途 |
|---|---|---|
| `BattleManager.BattleCoroutine` | 唯一真实结算 | 正式战斗 |
| `PlayerData.TryFight` | **死代码**（零调用者） | 早期原型，不走祝福系统 |
| `MonsterManualEntryUI.SimulateBattle` | 活的 | 图鉴「损失 HP」预测 |

**图鉴 `SimulateBattle` 的口径**：白板对打，完全不跑祝福系统。
从 `enemy.hp` 开打，逐回合累加玩家会掉的血；每回合玩家先手。
- 玩家伤害 = `(Attack - 敌防) × AttackCount + min(魔力充能, 魔力上限)`
- 先手偷袭：敌速 > 我速 → `敌伤害 × 2`，再乘我方减伤
- 累加项：偷袭、敌方反击、**攻方反伤**（我打敌时敌反伤算我的损失）
- 不计入：吸血回复（`Heal` 会被 `hpMultiplier` 放大，图鉴直接忽略）、
  所有祝福（爱/深渊/静默/工匠/智慧/异乡人/灵知/真理）全部不生效
- 返回 −1 的两种情形：初期就算不出伤害；或跑满 `maxTurns=10000` 还没打死敌人
  （与实战的 `MaxTurnCount=200` 判负不是一回事）

**已确认的口径差异（都还没修）**：
1. 缺 `MagicAmplifier` 倍率（实战 `BattleManager` 有；图鉴按 ×1 算）。
2. **敌人吸血基数不同**：实战 `enemyPhysical * enemy.LifeSteal/100`（未过玩家减伤），
   图鉴 `actualToPlayer * enemy.lifeSteal/100`（已过玩家减伤）。
   玩家减伤 > 0 时两者不等 → 图鉴低估敌人回血。
3. 图鉴无法打开于战斗中（`PlayerMove.manualShortcutLocked` 含 `isInBattle`），
   所以它读 `player.Attack` / `player.Defense` 时 `inBattle == false`，拿到的是真实字段 —— 改造后仍然正确。
