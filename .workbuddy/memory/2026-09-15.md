## 战斗「跳过」档：不打开战斗界面，直接结算

用户需求：设置里选中「跳过」时，战斗 UI 完全不打开，直接出结果。

### 实现（全在 `BattleManager.cs`，Unity 运行中只改 .cs）
- 新增 `[SerializeField] float skipDelayThreshold = 0.05f` + `public bool IsSkipMode => logDelay <= skipDelayThreshold;`
  - 用**阈值**而非 `== 0.01f`：速度值来自存档 JSON（`SaveManager.LoadBattleSpeed`），浮点比较不可靠；
    正常/两倍/四倍 = 1 / 0.5 / 0.25，离阈值很远不会误判。存档格式不用改，零迁移。
- 新增私有 `bool silentBattle`，在 `StartBattle` 里 `= IsSkipMode`（每次开战重新赋值，不需要复位）。
- 静默化的四处：
  1. 8 处 `yield return new WaitForSeconds(logDelay);` → `if (!silentBattle) yield return ...`（内联，不加额外帧；
     没用 `yield return WaitLogDelay()` 这种嵌套 IEnumerator，语义不直观）
  2. `battleUI.OpenBattle(...)` → 跳过档不调用
  3. 两处 `playerData.PlayHurtAnimation()` → 加 `!silentBattle &&`（该方法除了驱动头像，还会
     `BodyAnimator.SetTrigger` 打在世界精灵上，跳过档不能让它抖）
  4. `CloseAfterDelay()` 的 1 秒 → 跳过档免掉
- `PlayAttackAnimation` / `PlayEnemyHit` / `PlayEnemyDeath` **不用改**：它们最终都走
  `BattleUI` 的 `if (!IsOpen) return;`，窗口没开就是空操作；`AddLog`/`UpdateXxxPanel` 只写 TMP 文本，
  对象 inactive 也照写不报错，所以整条结算路径可以原样复用。
- `OnBattleOpen` / `OnBattleClose` 仍成对发出（同帧），`PlayerMove.isInBattle` 配对收放不会卡锁定态。

### ⚠️ 必须记住的坑
**跳过档下整个战斗循环在 `StartCoroutine` 的第一次 MoveNext 里同步跑完**（所有等待被免掉 → 没有 yield）。
因此任何"双方都打不动对方"的循环会**永久卡死编辑器**（`EnemyController.TakeRawDamage` 会因
`damageReduction >= 100` 返回 0，而玩家 `SubtractHP` 无视减伤、`enemyPhysical` 又可能为 0 → 谁都不死）。
→ 新增 `private const int MaxTurnCount = 200;`，超限 `EndBattle(false)` 强制收场（判负 = 没打赢，
敌人留在原地、玩家不死），正常档也受这道闸保护。

### 已知留白（用户未要求，待确认）
- 跳过档下**没有任何结算反馈**：日志写进没显示的 UI，赢了靠"敌人消失 + 金币涨"、
  输了靠"HP 掉 + 不移动"间接感知。项目里没有 Toast/浮动文字系统，要做需新建。
- `skipDelayThreshold = 0.05` 是新增 Inspector 字段，场景里的 BattleManager 没有该字段的序列化值 →
  Unity 会用 C# 默认值，行为正确（打开工程后可自行调）。
