### ExitTime 概念备忘（用户问过）
- `m_ExitTime`（0~1 归一化）= 「源状态播到百分之几才允许离开」。`m_HasExitTime` 没勾时它**完全无效**（灰掉）。
- **Has Exit Time 和 Conditions 是 AND**：想「条件一到就走」必须 HasExitTime=0（duration 也设 0 = 硬切，无过渡）。
- `m_TransitionDuration` = 混合时长，不是等待时长。它 > 0 时会把源状态和目状态**混合**，看起来就是「慢慢淡过去」。
- 典型两段式：进入用 `HasExitTime=0 + duration 0`（立刻）；收尾用 `HasExitTime=1 + ExitTime=1 + duration 0`（播完就回）。
- 陷阱：`duration > 0` 的那段混合是**从 ExitTime 那一刻开始算**的，所以 ExitTime 0.516129 + duration 0.2478
  = 0.2667s 就开始淡出，而不是播到 0.2667s 才淡出。

### 重新分析后的结论
受击做成「独立叠加对象」后，原来的难题（共享片段必须兼容 44 个不同 idle）**自动消失**：
特效只写它自己的 SpriteRenderer → 一个共享特效资源对所有敌人成立，**不需要 Override Controller**。
「挂两个控制器」在同一 GameObject 上仍不行，但挂到独立对象上是合法且不冲突的（写的是不同 renderer）。

### 三个必须绕开的坑
1. **特效绝不能带 Collider2D（或必须在不在 `obstacleMask` 的层）**。
   `PlayerMove.TryMove`：`obstacleMask = door|wall|enemy|item|stair|npc`，`hit = hits[0]`，
   然后在 `hit` **自己身上** `GetComponent<EnemyController>()`。特效若有碰撞体且层进了 mask，
   玩家撞到会拿到特效的碰撞体 → 组件在父对象上 → 返回 null → **战斗完全不触发**。
2. **`m_SortingOrder` 必须 > 4**（敌人是 4）。
3. **特效要做平级对象，不能做敌人的子对象**：`EnemyController.Defeat()` 里有 `gameObject.SetActive(false)`，
   子对象会被一起掐掉，致命一击的特效播一半就没了。

### 敌人受伤的所有入口（接线面）
`EnemyController.TakeDamage` / `TakeRawDamage` / `SubtractHP` 是唯一漏斗。调用点：
`BattleManager.cs:205`（玩家攻击）、`:262`（玩家反伤）、`:99`（减半道具 `SetHP`）、
`PlayerData.cs:169`（反伤）、`PincerAttack.cs:265`（玩家夹击敌人）、`PincerAttack.cs:46`（回血，别触发）、
