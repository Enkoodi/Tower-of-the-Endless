## NPC 对话：选项后的「后续对话」+ 战斗胜利后自动续接

**需求**：点击接受/购买、拒绝/取消之后（若该选项开了一场战斗，则战斗胜利之后）再弹对话框说后面的话。

**结论**：能实现，**不需要新增脚本**，但要改 `DialogueUI.cs` —— 原来 `OnChoice1Clicked` 里是
「`Invoke()` 完就 `CloseDialogue()`」，写死了"选项即结束"，连"点完接着播另一段"都做不到。

改动（`.workbuddy/backup/选项后续对话_20260922/` 存了改动前的三个文件）：
- `DialogueTrigger`：新增 `choice1NextLineIndex` / `choice2NextLineIndex`（-1=结束对话，>=0=点击后从该句继续）。
- `DialogueUI`：
  - 打开时**复制** `dialogueLines` 与选项文本 → NPC 在选项里被 `NpcRemover`/`NpcBattler` 销毁后仍能播；
  - `ExecuteChoice` 统一处理：先收起面板 → 执行选项事件 → 战斗中则记下待续接句等战斗结束，
    否则直接跳到续接句，没续接句就照旧关闭；
  - 订阅静态事件 `BattleManager.OnBattleClose` 做战后弹回，新增 `panelShown` 保证
    `OnPanelOpen/OnPanelClose` 成对（不重复发关闭事件）。
- `BattleManager`：新增 `LastBattleWon` 属性（战后续接只认胜利）。
- 选项句想要出现按钮，其 `nextLineIndex` 仍是 **-2**（显式结束）或它本来就是最后一句；
  续接句就放在数组后面，线性流程走不到它们。

**踩到的两个坑**：
1. **跳过档时序**：战斗速度选「跳过」时整场战斗在 `choiceEvent.Invoke()` 内部**同步**跑完，
   `OnBattleClose` 当场触发 —— 所以「待续接句」必须在 Invoke **之前**就写好，否则战后不会弹回来。
2. 同一消息里并行发多个 Edit 会**静默丢改动**（两处都报 success，只落盘后一处）；
   已把这情形补进 `unity-editor-safe-edit` 技能第 3 节。

## 第五轮：修「战斗触发器与敌人同格时不触发」（27F）

**症状**（用户报）：27F 的 `27FBattleTrigger 1`（物体 id 28）在 (5,11)，同格 `enemies` 层还有敌人 18，
击败敌人后触发器不生效，要走出去再进来才触发。

**根因**：`PlayerMove.TryMove` 里 `hit = hits[0]` —— `Physics2D.OverlapCircleAll` 的返回顺序不确定，
同格两样东西只处理一个。敌人先被取到 → 开打并 `return`，触发器那一支永远走不到；
打赢后 `OnBattleEnd` 是「先开打再 SmoothMove 走进去」，不经过 TryMove，所以落点格也不会补检。
（顺序反过来更糟：触发器先被取到 → 玩家**直接走进敌人格、不打架**。）

**改法**（只改 `Assets/Scripts/Player/PlayerMove.cs`，编辑器运行中，未碰场景/prefab）：
1. 触发器不再参与占位物分流：遍历 `hits` 先激活所有 `BattleTrigger`（`Trigger()` 本身幂等），
   `hit` = 第一个非触发器 —— 与敌人/道具同格也照样触发；原来的 `BattleTrigger` 专属分支删除。
2. 新增 `TriggerOnCell(worldPos)`，在 `SmoothMove` 落点后补检一次 —— 覆盖「战斗胜利后走进该格」这条路。
3. 顺手把重复的层遮罩提成 `ObstacleMask` 属性。
门优先分支保持不动（门挡着时不激活触发器，是既定设计）。

**证据**：
- 新增只读脚本 `.workbuddy/tools/battle_trigger_overlap.py`（触发器位置 + spawnPositions + 同格冲突）
  与 `.workbuddy/tools/map_cell_conflicts.py`（**全地图同格叠加普查**）。全 39 层里同格叠加只有 2 处：
  27F (5,11) 触发器+敌人（本次修的）、`floor_-07` (8,0) 门+神圣火花（门优先正常流程，非 bug）。
- 模型对拍 `.workbuddy/backup/battle-trigger-same-cell_2026-09-22/model_compare_cell_dispatch.py`：
  584 组「格子内容 × hits 顺序」枚举，**无触发器却行为不一致 0 处、有触发器却不生效 0 处**；
  44 组带门的走既定例外分支，57 组属于本次有意修复。
- `cs_brace_check` 通过（620 行配平）；`obstacleMask`/`hits[0]` 已无残留引用。
