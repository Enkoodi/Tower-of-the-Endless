# 字体缺字（方块）诊断报告

日期：2026-09-20　范围：`Assets/Font/smiley-sans-v2.0.1/` + `Assets/TextMesh Pro/Resources/TMP Settings.asset`

## 一句话结论

**不是字体设置写错了，是动态图集被填满了。** 每个字体资产的 2048×2048 图集在 `pointSize=90 / padding=9` 下最多只能装约 450 个字形，而项目实际要显示 865 个字符（其中汉字 680 个）。图集早已到顶，任何"第一次出现"的字都排不进去，就被替换成 U+25A1 □。

## 证据

### 1. 图集占用率（实测）

| 字体资产 | 图集 | 已烘焙字形 | 占位率 | 最右/最下边界 | 剩余只够 |
|---|---|---|---|---|---|
| SmileySans-Oblique SDF | 2048² | 450 | **89.8%** | x=2046 / y=2047 | ~50 字 |
| culiufangxin24x SDF | 2048² | 390 | **93.1%** | x=2047 / y=2046 | ~28 字 |
| xiangcuilingduhei SDF | 2048² | 366 | 92.1% | 铺满 | —— （未被引用） |
| 零ゴシック SDF | 2048² | 52 | 12.2% | —— | —— （未被引用） |

四个资产都是 `m_AtlasPopulationMode: 1`（Dynamic 动态），但 `m_IsMultiAtlasTexturesEnabled: 0`
——**不允许开第二张图集**。图集一满就永久满。

平均每个字形 92×92 像素（450 字 × 8374px = 3.77M px / 4.19M px）。
剩余 426k px 虽然还有 354 个空闲矩形，但都被切成了放不下一个 92×92 字形的碎片，所以实际上已经满了。

### 2. 编辑器日志里的直接证据

`%LOCALAPPDATA%\Unity\Editor\Editor.log`：

```
The character with Unicode value \u5F02 was not found in the [SmileySans-Oblique SDF]
font asset or any potential fallbacks. It was replaced by Unicode character \u25A1
in text object [BlessingName].
```

- `\u25A1` 就是 □。TMP 源码 `TMPro_Private.cs:1161` 写死了 `missingGlyphCharacter == 0 → 9633 (U+25A1)`。
- "or any potential fallbacks" —— 确认**没有任何 fallback 链**兜底。
- 本次会话 27 条、上一次会话 34 条警告；两次会话缺失的字符集合不同且在扩大，正是"刚开始好好的、后来越来越多"的表现。

失败字符（近两次会话）：乡 亡 军 剑 圣 垒 壁 复 守 少 屈 异 总 恢 意 慧 智 死 泌 甲 疾 盾 / 升 后 咏 唱 噬 择 束 结

全是常用字——说明源字体里有，只是图集塞不下。

### 3. 源字体覆盖

| 源字体 | 总码点 | 汉字 | 项目 680 个汉字中缺失 |
|---|---|---|---|
| SmileySans-Oblique.ttf | 9440 | 8057 | 0 |
| culiufangxin24x.ttf | 7540 | 6763 | 0 |
| xiangcuilingduhei.ttf | 11603 | 10083 | 0 |
| **零ゴシック.otf** | 8262 | 6720 | **348**（日文字形集，缺大量简体字） |

前三个源字体够用，问题 100% 在图集容量。**零ゴシック 不要使用**（缺 348 个常用简体字，且当前未被任何场景引用）。

### 4. 其他两个次要问题

- `TMP Settings.asset` → `m_defaultFontAsset` 指向 **LiberationSans SDF**（无任何中文字形）。
  新建 TMP 文本默认就是它，一旦忘了换字体，整段中文全变方块。`m_fallbackFontAssets: []` 也是空的。
- `m_GetFontFeaturesAtRuntime: 1`：动态字体每加一个字形都要重新注册 OpenType 特性，中文场景下是纯损耗。
- `renderMode: 4165` = **SMOOTH_HINTED**，不是 SDF（Unity 自带的 LiberationSans SDF 用的是 4169 = SDFAA_HINTED）。
  文件名叫 "SDF" 是误导——现在图集里存的是 90pt 位图，放大到 80px 以上会糊。

## 为什么"没动设置也会突然缺字"

1. 动态字体每渲染一个**从没出现过的字**，就往图集里刻一个字形。
2. 图集只能刻约 450 个。随着内容铺开（祝福名/描述、道具、敌人、对话），刻度数一路上涨。
3. 到某个时刻刻满了 → **下一个新字开始变方块**，且此后所有新字都是方块。
4. 从用户视角看：没有改任何设置，同一个界面昨天还好好的，今天某个词突然就方块了。
   ——因为那个字昨天刚好排得进去，今天新的字把最后一点空隙吃掉了。

另外两个会"凭空"丢字的坑：

- **git 回滚会让已刻好的字形消失。** 动态字形是写回 `.asset` 的（这两个文件当前在 git 里就是 `M` 未提交状态）。
  一旦 `git checkout` / `git stash` 把 `.asset` 还原，之前刻进去的字全部消失；此时图集已满，**再也补不回来**。
- **Unity 强退/崩溃**会丢掉本次会话新增的字形（TMP 靠保存资产落盘），同样补不回来。

## 修复方案

### 方案 A：立刻止血（1 分钟，无质量损失）

在 Unity 里选中这两个字体资产，Inspector 勾上 **Multi Atlas Textures**：

- `Assets/Font/smiley-sans-v2.0.1/SmileySans-Oblique SDF.asset`（45 个组件在用）
- `Assets/Font/smiley-sans-v2.0.1/culiufangxin24x SDF.asset`（16 个组件在用）

图集满时 TMP 会自动开新页（`TMP_FontAsset.cs:2115 SetupNewAtlasTexture`），
多页渲染由 `TMP_MaterialManager.GetFallbackMaterial`（`TMPro_Private.cs:1260`）处理，开箱即用。
代价：每多一页多 2048²（约 4MB，Alpha8）常驻显存；本项目约需 2 页。

### 方案 B：正规做法（推荐长期采用）

用**预烘焙全套字符**重做两个字体资产：

1. Font Asset Creator 里字符集选 **Characters from File**（或 Custom Characters），
   喂入 `.workbuddy/font/字符集_单行.txt`（865 个字符，含全项目汉字/标点，已生成好）。
2. Render Mode 改 **SDFAA**（而不是现在的 SMOOTH_HINTED）。
3. 建议 Sampling Point Size = **48**、Padding = **5**：单张 2048² 可容约 1225 字形，一张就够，
   且 SDF 放大不糊（当前 UI 最大字号 80）。
4. 仍勾上 Multi Atlas Textures 作为余量。
5. **按上面参数点 Generate → 点 `Save`（不是 `Save as...`）**。
   已确认 TMP 3.0.7 的 Save 会覆盖同一个文件、GUID 不变
   （`TMPro_FontAssetCreatorWindow.cs:1099` 注释即 "Save over exiting Font Asset"），
   所以引用这两个字体的 61 个组件一处都不用改。

好处：运行期不再动态改图集（不会再有"玩着玩着突然方块"）、内存和包体可控。

#### B 做完之后，`Atlas Population Mode` 选 Dynamic 还是 Static？

| | Dynamic（保持现状，**推荐**） | Static |
|---|---|---|
| 已预烘焙的 865 字 | 张张都在图集里，运行时**不会**再动态加，无脏写 | 同左 |
| 以后冒出一个新字 | **自动补进图集，不方块**；多页兜底 | **永久方块，必须重做** |
| 构建体积 | 需保留源字体（Include Font Data），+约 7MB | 可清掉源字体引用，更小 |
| 资产是否随运行变化 | 只在新字出现时才写盘（预烘焙后基本不会） | 永远不变，完全确定 |

**结论：保留 Dynamic。**预烘焙把"常见字"固化掉，Dynamic 只当保险丝——
两边好处都拿到，代价只是构建里多保留源字体。

#### 那什么时候才需要重跑？

只有当**项目文本真的出现原字符集里没有的字**时才需要。
判断不需要靠肉眼——直接再跑一次导出脚本，它会和上次清单比对：

```
python .workbuddy/tools/font_charset.py
```

- 输出 `✔ 字符集与上次完全一致 → 不需要重做图集` → 什么都不用做
- 输出 `⚠ 字符集有变化 → 需要重做一次字体图集` 并列出新增的字 → 那时再走一遍上面 5 步

（脚本每次运行都会更新 `.workbuddy/font/字符集_清单.json`，所以这个提示是准的。）

### 顺带一定要改的

- `TMP Settings.asset` → **Default Font Asset 改成 SmileySans-Oblique SDF**，别留 LiberationSans（无中文）。
- 给两个字体资产配 **Fallback Font Asset Table** 互相兜底（SmileySans ↔ culiufangxin24x）。
- 删掉或彻底不用 `零ゴシック`（缺 348 个简体字）、`xiangcuilingduhei`（未被引用却占 8.6MB 资产）。

## 操作注意

- **不要把 `*.asset`（字体图集）当普通文本文件回滚**。重做（方案 B）之后图集内容已经完整，
  可以放心提交；回滚它只会把字弄丢。
- 方案 A 与方案 B **不冲突**：B 之后 Multi Atlas Textures 仍建议保持勾选，当新字的兜底。
- 方案 B 重做前，先把这两个 `.asset` 的当前未提交改动备份一份
  （它们是 git 里的 `M` 状态，覆盖后就回不去了）。
